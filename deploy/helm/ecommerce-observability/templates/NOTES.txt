{{- if .Values.ingress.enabled }}
Host access goes through an ingress controller. This chart renders the Ingress
but does not install a controller — that is a one-time cluster add-on:

  helm repo add ingress-nginx https://kubernetes.github.io/ingress-nginx
  helm install ingress-nginx ingress-nginx/ingress-nginx \
    --namespace ingress-nginx --create-namespace

Docker Desktop publishes LoadBalancer service ports to the host, so once the
controller is running the stack is reachable at:

  http://127.0.0.1/health
  http://127.0.0.1/products

Place an order:

  curl -X POST http://127.0.0.1/order \
    -H 'Content-Type: application/json' \
    -d '{"customerId":"cust-1","items":[{"itemId":"00000000-0000-0000-0000-000000000001","quantity":1}]}'

Use 127.0.0.1 rather than localhost: on Windows localhost resolves to ::1
first, and the published port is not bound on IPv6, so requests hang.

NodePorts are deliberately not used: Docker Desktop's kind-based cluster does
not publish them to the Windows host.

Inject network chaos on the payment path (the proxy starts with no toxics):

  kubectl port-forward svc/toxiproxy 8474:8474
  # then follow toxiproxy/scenarios.md
